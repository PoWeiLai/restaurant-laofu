# 好味牛肉麵 — 掃碼點餐系統

**內用**：客人掃桌上的 QRcode → 手機點餐 → 訂單即時進廚房看板 → 廚房照單製作 → 吃完櫃檯結帳。
**外帶**：客人在家用手機開 `/takeout` 點好 → 拿到取餐號 → 時間到來店報號碼取餐、現場付款。

兩邊共用同一份菜單、同一個廚房看板，不需要服務生來回抄單。

> 「好味牛肉麵」是示範用的虛構店名，電話與地址也是假的。店家資料在後台
> **「店家設定」**裡改，不寫死在程式碼中，換一家店不必改程式重新部署。

## 每天開店怎麼用

在店內那台電腦開一個終端機，執行：

```bash
npm start
```

畫面會印出三個網址，例如：

```
店內網址   http://192.168.50.2:3001
廚房看板   http://192.168.50.2:3001/kitchen
後台管理   http://192.168.50.2:3001/admin   （店員密碼 1234）
```

- **廚房**：平板或螢幕開 `/kitchen`，整天掛著就好，新單會自動跳出來並響提示音
- **櫃檯/老闆**：開 `/admin` 改菜單、列印 QRcode、結帳
- **客人**：掃桌上 QRcode 進 `/t/桌號`

> 客人手機必須連上**店內同一個 WiFi**，否則掃了打不開。

## 第一次設定

1. `npm install`
2. `npm run build`（建置前端；改過前端程式碼才需要重跑）
3. `npm start`
4. 用瀏覽器開 `/admin` → 輸入密碼 `1234` → 到「菜單管理」把菜單建好
5. 切到「QRcode 列印」→ 按「列印全部 QRcode」→ 剪下貼在 1～10 號桌上

### 改店員密碼

```bash
set STAFF_PIN=你的密碼 && npm start        # Windows cmd
$env:STAFF_PIN='你的密碼'; npm start        # PowerShell
```

### IP 會變怎麼辦

路由器每次可能配不同 IP，QRcode 就失效了。建議在路由器把這台電腦設成**固定 IP**（DHCP 保留）。
若要指定固定網址，可用：

```bash
set PUBLIC_URL=http://192.168.50.2:3001 && npm start
```

## 菜單怎麼建

三種方式，挑一種：

1. **後台一道一道加** — `/admin` →「菜單管理」→ 先新增分類，再逐項填品名/價格
2. **整本貼上匯入** — 同頁最下方「批次匯入菜單」，每行一道：
   ```
   熱炒,宮保雞丁,180,微辣
   熱炒,蒼蠅頭,160
   飲料,烏龍茶,30
   ```
   格式是 `分類,品名,價格,說明`（說明可省略）
3. **改種子檔重灌** — 編輯 `server/menu.seed.json` 後執行 `npm run seed:menu`
   （會清空現有菜單再匯入，適合一次性建置）

**菜色照片**：在「菜單管理」每一列最左邊點「＋圖片」直接上傳，檔案會存到 `public/images/`。

目前 19 道菜中有 13 道帶照片，全部是從店家菜單看板原圖裁切出來的。原始素材放在 `menu-source/`，
**這個資料夾不進 repo**（`.gitignore` 已排除）——那是店內看板的實拍照，拿來當 demo 給別的餐廳看時，
照片比店名更容易被認出是哪一家。**沒有照片的品項，客人端會自動顯示品牌色字卡**，不會出現空白破圖。
要補照片就用手機拍好，從後台該道菜的「＋圖片」上傳即可，不必改程式。

重新裁切菜單原圖的方式（需要 `sharp`，已列在 devDependencies）：

```bash
node -e "require('sharp')('menu-source/檔名.jpg').extract({left:0,top:0,width:300,height:200}).resize({width:600,height:450,fit:'cover'}).toFile('public/images/新檔名.jpg')"
```

## 選項（湯／乾、麵種、份量、加點）

菜單上的勾選格子做成「選項群組」，定義在 `server/menu.seed.json` 的 `optionGroups`：

| 群組 | 必選 | 內容 |
| --- | --- | --- |
| 湯麵還是乾拌 | ✅ | 湯麵、乾拌麵 |
| 麵的選擇 | ✅ | 細圓麵、刀削麵、拉麵 |
| 份量 | ✅ | 小碗 +0、大碗 +60 |
| 份量（原汁牛肉湯麵） | ✅ | 小碗 +0、大碗 +20 |
| 選部位（好味家常牛肉麵） | ✅ | 牛腱、肋條、綜合 |
| 選部位（精選老饕牛肉麵） | ✅ | 牛三寶、牛肋排 |
| 加點 | 選填（可複選） | 加麵 +20、加肉 +50 |
| 附贈小碟涼菜 | ✅ | 紅油劍筍／涼拌雪菜／和風翡翠／涼拌海帶絲 免費擇一（每日隨機） |

每道菜在 `items[].options` 列出要掛哪些群組。例如炙燒雪花牛肉麵：

```json
{ "name": "炙燒雪花牛肉麵", "price": 135, "options": ["湯乾", "麵種", "份量", "加點", "小碟涼菜"] }
```

- 客人點有選項的菜時，會跳出選單而不是直接加入購物車
- **必選沒選不讓送出**（例如沒選湯麵或乾拌）
- 加價一律由**伺服器**計算，前端傳來的價格不採信
- **同一道菜不同選法會分成兩列**（乾拌麵和湯麵各自計數）
- 廚房看板會把選項用大字印在品名下方，備註用紅字

改完選項或菜色後執行 `npm run seed:menu` 重新匯入。

## 日常操作

| 情境 | 怎麼做 |
| --- | --- |
| 某道菜賣完了 | 後台 →「標售完」，客人端立刻變灰、不能點 |
| 臨時調價 | 後台 →「改價」。**已送出的訂單不受影響**（下單當下就存了價格快照） |
| 客人加點 | 客人在同一個 QRcode 頁面再點一次即可，會併入同一桌帳單 |
| 內用結帳 | 後台 →「內用帳單」→ 選現金／刷卡／行動支付。結完該桌歸零，下一組客人重新開單 |
| 外帶收款 | 後台 →「外帶訂單」→ 找到取餐號 → 選現金／刷卡／行動支付 |
| 印帳單 | 「內用帳單」→「列印帳單」 |
| 改店名電話 | 後台 →「店家設定」，存檔後客人端立刻更新，不必改程式重新部署 |
| 忙不過來想停外帶 | 後台 →「店家設定」→ 取消勾選「開放外帶線上訂餐」 |
| 看今天做多少 | 後台 →「今日報表」，內用／外帶分開列，另有熱銷排行 |

廚房看板：訂單等超過 15 分鐘會整張變紅色提醒；外帶單的抬頭是紅色的「外帶 + 取餐號」，
右上角會寫預約取餐時間，不會跟桌號搞混。

## 點餐到收錢的流程

### 內用：先吃後付

掃桌上 QRcode → 點餐 → **直接進廚房，不必先付款** → 吃完到櫃檯結帳。

結帳依據是「桌次（session）」：同一桌從入座到結帳之間的所有訂單自動累積成一張帳單，
所以客人加點三次也只結一次帳。後台「內用帳單」列出每桌目前未結的金額，按下去選付款方式就結清，
那一桌隨即歸零，下一組客人掃同一張 QRcode 就是全新的帳單。

### 外帶：先做後付，靠取餐號對單

客人在 `/takeout` 點餐 → 留姓名與電話、選取餐時間 → 拿到**取餐號**（每天從 001 開始）
→ 廚房照做 → 客人到店報號碼 → 櫃檯按「收款」。

外帶的實際風險是客人放鴿子，所以後台「店家設定」有兩個開關可以按店家習慣調整：

- **外帶單先由店員確認再進廚房**：單子會先停在「待接單」，店員（大單可以先打個電話）按
  「接單，送進廚房」才會出現在廚房看板。新客多或怕白做時打開。
- **外帶開放線上先付款**：見下一節。

客人送出後會跳到取餐號畫面，那組查詢碼存在他自己的手機上，之後從「我的訂單」還找得回來，
店家改狀態時客人那頁會即時更新（已接單 → 製作中 → 可取餐）。

### 線上付款目前是「模擬付款」

`payment_provider` 預設是 `mock`：客人按「線上先付」會顯示已付款、後台也會標示已線上付款，
但**不會真的收到錢**，用途是讓 demo 把整條流程走完。客人端與後台都有明顯提示，不會誤導店家。

要真的收錢得接金流（綠界 ECPay／藍新／LINE Pay），改的位置在
`server/index.js` 的 `/api/takeout/:code/pay-online`，那裡寫了要改成三步：建立交易 →
金流商回呼 → **驗過簽章才寫入已付款**。在那之前絕對不要因為前端說付好了就標記付款。

## 開發

```bash
npm run dev        # 同時啟動後端 (3001) 與 Vite 前端 (5173)
npm run build      # 建置前端到 dist/
npm start          # 正式模式，單一 port 3001 同時供應前端與 API
npm run seed:menu  # 用 server/menu.seed.json 重灌菜單
```

## 架構

```
server/
  index.js       Express API：菜單、訂單、廚房、後台、QRcode、帳單
  db.js          SQLite schema（用 Node 24 內建 node:sqlite，免安裝原生模組）
  events.js      SSE 推播，廚房不必輪詢就能即時收單
  seed.js        菜單種子匯入
  menu.seed.json 菜單原始資料
src/
  views/OrderPage.vue      客人點餐（手機版）／內用與外帶共用
  views/TakeoutStatus.vue  外帶訂單進度與取餐號
  views/Kitchen.vue        廚房看板
  views/Admin.vue          後台：菜單 / QRcode / 帳單 / 外帶 / 報表 / 設定
  api.ts                   前端 API 封裝
  takeout.ts               客人手機上的外帶訂單記錄（只存查詢碼）
data/restaurant.db      營運資料（含訂單與帳單，記得備份）
public/images/          菜色照片
```

### 資料表

- `tables` — 1～10 號桌
- `sessions` — 一桌從入座到結帳為一個 session，內用帳單以此結算
- `orders` / `order_items` — 訂單與明細，明細存下單當下的品名與價格
  - `type` 區分 `dine_in`（內用，掛在 session 底下）與 `takeout`（外帶，沒有桌號也沒有 session）
  - 外帶另有取餐號、查詢碼、取餐人、預約取餐時間與自己的收款欄位
- `categories` / `menu_items` — 菜單
- `settings` — 店名、電話、外帶開關等，店家在後台自己改，不寫死在程式裡

### 備份

整個系統的資料都在 `data/restaurant.db` 這一個檔案，關掉程式後複製走即可。

## 部署到雲端（交付給店家）

在店內電腦跑 `npm start` 的模式，電腦一關店家就不能點餐。若要交付給店家自行營運、
與開發者的電腦脫鉤，就把系統部署到 24 小時運作的主機上（以下以 Zeabur 為例）。

### 步驟

1. 把這個專案推上 GitHub
2. Zeabur 建立 Project → Add Service → 選 GitHub → 選這個 repo
   （會自動偵測 `package.json`，跑 `npm run build` 再 `npm start`）
3. **掛 Volume**（不做這步，主機一重啟訂單和照片全沒了）
   - Mount Directory 填 `/data`
4. 設定環境變數：

   | 變數 | 值 | 用途 |
   | --- | --- | --- |
   | `STAFF_PIN` | 自訂密碼 | 店員登入 `/admin`、`/kitchen`，**一定要改掉預設的 1234** |
   | `DATA_DIR` | `/data/db` | 訂單資料庫存放位置，指向 Volume |
   | `IMAGES_DIR` | `/data/images` | 店家上傳的菜色照片，指向 Volume |
   | `PUBLIC_URL` | `https://你的網址` | QRcode 裡要寫的網址 |

5. 開 Domain 拿到網址後，回填 `PUBLIC_URL` 再重新部署一次
6. 進 `/admin` →「QRcode 列印」→ 列印全部 → 貼到桌上

### 第一次啟動會自動做的事

- 建立資料庫、開 1～10 號桌
- 菜單是空的就自動匯入 `server/menu.seed.json`（5 個分類、19 道菜）
- Volume 是空的就把內建菜色照片複製進去

所以部署完直接就能用，不必另外跑 `npm run seed:menu`。

### 交付後店家自己能做的事

改菜單、改價格、標售完、上傳照片、結帳、印帳單、看報表、重印 QRcode，
以及在「今日報表」頁按**「下載備份」**把營運資料存到自己的電腦（建議每月一次）。

### 注意

- 部署到雲端後，**店家網路斷線就不能點餐**（跑在店內電腦的模式則不受影響）
- 免費方案沒有 Volume，資料會在主機重啟時被清空，**只能拿來展示，不能真的營業**
- 目前是單店設計。第二家店要另外開一個 Project，不能共用同一個網址

### 用 Render 部署（免費方案，僅供展示）

專案根目錄的 `render.yaml` 已寫好設定，到 Render 按 **New → Blueprint** 選這個 repo
即可自動建立服務。建立時 Render 會問 `STAFF_PIN` 要填什麼（密碼不寫進 repo，免得公開的
repo 等於把店員密碼貼出來），填一組自己記得的即可；之後要改，到服務的 **Environment**
頁改再重新部署。`PUBLIC_URL` 不用設，程式會自動讀 Render 提供的
`RENDER_EXTERNAL_URL`，QRcode 就會指向線上網址。

免費方案的限制讓它**只能展示、不能營業**：

- 15 分鐘沒流量就休眠，下次開啟要等約 1 分鐘
- 沒有永久硬碟，重新部署或重啟會清空訂單與店家上傳的照片
  （內建菜單與照片會自動重新匯入，畫面仍是完整的）
- 每月 750 小時額度

要正式交付給店家營業，改用有永久硬碟的付費方案或其他主機，並依前一節設定
`DATA_DIR` / `IMAGES_DIR`。

## 伺服器休眠怎麼解（客人掃碼要等幾十秒）

Render 免費方案 15 分鐘沒流量就休眠，下一位客人掃碼要等約 50 秒才看到畫面——
店家會抱怨的就是這個。兩層解法：

**第一層：保溫（免費，先做這個）**

程式已內建 `/api/health` 這支極輕量的端點（不查資料庫），外面定時打它服務就不會睡著：

1. 到 [cron-job.org](https://cron-job.org) 註冊（免費）
2. Create cronjob
3. **URL** 填 `https://你的服務.onrender.com/api/health`
4. **Schedule** 選 Every 10 minutes（不要設 1 分鐘，免費方案每月只有 750 小時額度，
   全天候保溫約用掉 720 小時，已經很接近上限）
5. 存檔。之後在 cron-job.org 的執行紀錄看得到每次都回 200，就代表有在保溫

**第二層：前端的喚醒畫面（已內建）**

萬一還是睡著了（保溫排程掛掉、或剛部署完），任何一支 API 超過 2.5 秒沒回應，客人畫面會
自動蓋上「正在為您開爐…」加秒數計時，而不是白畫面。客人知道是在等、不會狂重整
（狂重整只會更慢）。這段在 `src/components/WakeOverlay.vue`。

**真正的解法**是升級 Render Starter（約 US$7/月）：不休眠，而且才能掛永久硬碟。
免費方案沒有硬碟，**服務一重啟訂單資料就全部消失**——這比慢 50 秒嚴重得多，
真的要給店家營業一定要升級。`render.yaml` 裡 `plan` 與 `disk` 兩段的改法都寫好註解了。

## 給店家試用 7 天

部署時設環境變數 `TRIAL_UNTIL`，值是試用的**最後一天**（含當天）：

```
TRIAL_UNTIL=2026-09-19
```

到期後：

- 客人端送不出訂單（`/api/orders` 回 403「試用期已結束」），內用與外帶都停
- 菜單照樣看得到，畫面不會壞掉
- **店員仍可登入後台**看資料、看報表、按「下載備份」把營運資料帶走——不會把店家鎖在門外

試用期間首頁與啟動日誌都會顯示「還剩幾天」，方便你追。日期是用台灣時間（+08:00）算到
當天營業結束，伺服器放在新加坡也不會提早一天到期。

### 到期後要開通正式版

到 Render 服務的 **Environment** 頁，把 `TRIAL_UNTIL` 的值清空或整個刪掉 → Save →
服務自動重新部署，起來就是沒有期限的完整版。想延長試用就改成新的日期，一樣存檔即可。
**不必改程式、不必重新建立服務。**

> 資料會不會跟著沒？升級成付費方案並掛了永久硬碟就不會。如果還在免費方案，改環境變數會
> 觸發重啟，訂單資料就沒了——所以要給店家正式用，先升級再開通，順序不要反。

## 給多家店試用

一家店一個 Render 服務：按 Blueprint 再建一個，填各自的 `STAFF_PIN` 與 `TRIAL_UNTIL`，
各自有獨立網址與獨立資料庫，彼此看不到對方的訂單。店家拿到後自己進「店家設定」填店名、
電話、地址，不需要為了改店名重新部署。
